## Кадры с мячом

Ноутбук берёт два кадра из лекции L3 — фото здания ИУ с пурпурным мячом при дневном свете
и тот же кадр «под лампой» (вдвое тусклее и теплее). Источники по очереди:

| Приоритет | Источник | Условие |
|-----------|----------|---------|
| 1 | `lectures/L03-color-histograms/demo/ball-day.jpg`, `ball-lamp.jpg` | уже лежат в репозитории |
| 2 | те же файлы, скачанные с GitHub в `data/` | Colab, где репозитория рядом нет |
| 3 | синтетический фон с тем же мячом | всегда работает; числа другие |

Мяч в кадре **нарисован** (центр (190, 560), радиус 58 px), поэтому у занятия есть эталонная маска
и метрики recall / precision / IoU считаются честно, а не «на глаз».

## Веб-камера для трекера

Ячейка трекера снимает 30 кадров на калибровку и 60 на слежение. Что важно:

- **принесите яркий цветной предмет** — маркер, чехол телефона, обложку; в первые 2 секунды
  **заполните им квадрат в центре кадра** — по нему берутся границы H и S;
- предмет не красный? отлично; красный — тоже работает (диапазон через 0/179), но убедитесь,
  что в кадре нет другого красного;
- камера свободна: закройте Zoom/браузер с камерой, при «камера занята» — Restart Kernel;
- серый или чёрный предмет не подойдёт: у серого нет оттенка (слайд 55).

Нет камеры (Colab, ноутбук без камеры, `CVCOURSE_NO_CAMERA=1`) — ячейка сделает **синтетическое
видео**: мяч летит по фото ИУ по дуге, уменьшается, свет проходит «день → сумерки → день».
У синтетики известна истинная траектория, поэтому ошибка трекера измеряется в пикселях;
для зачёта это равноценно.
